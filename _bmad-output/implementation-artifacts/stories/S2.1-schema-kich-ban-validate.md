# Story S2.1: Schema kịch bản + validate

Status: ready-for-dev
Epic: 2 — Kịch bản & sinh dữ liệu · Sprint: 2
Phụ thuộc: S1.1 · Quyết định: QD-2 (YAML chuẩn gốc + chuyển đổi Excel)

## Story

Là người viết kịch bản, tôi muốn kịch bản được định nghĩa bằng file YAML có schema rõ ràng và được kiểm tra lỗi trước khi chạy, để kịch bản sai bị chặn từ đầu với thông báo chỉ đúng dòng/trường sai.

## Tiêu chí nghiệm thu (AC)

1. **AC-1:** Gói `packages/scenario-schema` định nghĩa schema YAML gồm: tên kịch bản, các vai tham gia, khối sinh dữ liệu, các bước theo vai (mỗi bước trỏ tới một hành động trong thư viện bước dùng chung — AD-2), điểm đồng bộ theo sự kiện (AD-3), khối kiểm đếm cuối (chỉ tiêu + nguồn đối chiếu).
2. **AC-2:** Hàm validate trả lỗi có cấu trúc: file, dòng, trường, lý do bằng tiếng Việt dễ hiểu; kịch bản hợp lệ trả về đối tượng đã parse dùng cho orchestrator.
3. **AC-3:** Có bộ chuyển đổi Excel → YAML: đọc file .xlsx theo mẫu cột đã tài liệu hoá, xuất YAML đúng schema; lỗi ô nào báo ô đó.
4. **AC-4:** Bộ test bao phủ: 1 kịch bản mẫu hợp lệ đầy đủ (đặt lịch → check-in → thanh toán → báo cáo), tối thiểu 8 trường hợp sai điển hình (thiếu vai, bước không tồn tại, điểm đồng bộ không có sự kiện sinh, chỉ tiêu kiểm đếm thiếu nguồn...).

## Việc cần làm (Tasks)

- [ ] Thiết kế + cài schema (zod hoặc tương đương) trong scenario-schema
- [ ] Parser YAML + validate + định dạng lỗi
- [ ] Bộ chuyển đổi Excel → YAML + file mẫu .xlsx
- [ ] Kịch bản mẫu hợp lệ dùng chung cho các story sau
- [ ] Test đơn vị cho AC-4

## Ghi chú cho dev (Dev Notes)

- Schema là hợp đồng trung tâm của hệ thống: thay đổi schema sau này phải tăng phiên bản (`schemaVersion`) và ghi chú tương thích.
- Kịch bản là dữ liệu, không phải code (AD-2): cấm nhúng mã tuỳ ý (eval/script) vào file kịch bản.
