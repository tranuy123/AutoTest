# Story S4.2: Reconciler — đối chiếu UI / API / DB

Status: ready-for-dev
Epic: 4 — Oracle & kiểm đếm báo cáo · Sprint: 3
Phụ thuộc: S4.1, S3.1

## Story

Là chủ dự án, tôi muốn cuối mỗi kịch bản hệ thống tự mở báo cáo và đối chiếu số liệu ở ba nơi với số kỳ vọng, để kết luận qua/hỏng dựa trên số thật chứ không dựa trên việc các bước có chạy hết hay không.

## Tiêu chí nghiệm thu (AC)

1. **AC-1:** Reconciler lấy đủ 3 nguồn cho mỗi chỉ tiêu kiểm đếm: số hiển thị trên giao diện báo cáo (qua worker), số từ API báo cáo của CRM, và số truy vấn trực tiếp từ DB của đích kiểm thử (chỉ đọc, qua cấu hình riêng, lọc đúng run_id/tenant test và khoảng ngày của kịch bản).
2. **AC-2:** Bảng chênh lệch cho từng chỉ tiêu: kỳ vọng / UI / API / DB / kết quả (Khớp hoặc Lệch + độ lệch). Một chỉ tiêu lệch ở bất kỳ nguồn nào → chỉ tiêu đó hỏng, và lần chạy bị đánh dấu hỏng ở khối kiểm đếm dù mọi bước thao tác đều qua.
3. **AC-3:** Lỗi đọc số trên UI do định dạng (ví dụ "900.000 đ") được xử lý bằng bộ phân tích số tiền dùng chung có test riêng — không so sánh chuỗi thô.
4. **AC-4:** Khi một nguồn không đọc được (API lỗi, DB không nối được), kết quả là "Không kiểm chứng được nguồn X" và lần chạy không được tính là qua.

## Việc cần làm (Tasks)

- [ ] Bộ đọc 3 nguồn + bộ phân tích định dạng số tiền/số lượng
- [ ] Bộ so sánh + sinh bảng chênh lệch, nối vào bản ghi lần chạy (S1.3)
- [ ] Test: ca khớp hoàn toàn, ca lệch UI, ca lệch DB, ca mất nguồn

## Ghi chú cho dev (Dev Notes)

- Quyền DB ở đây là chỉ-đọc và chỉ dùng trên đích kiểm thử/UAT theo cấu hình; tuyệt đối không ghi vào DB của CRM.
- Đây là story biến "chạy được" thành "đúng số" — không hạ chuẩn AC-2 vì bất kỳ lý do tiến độ nào.
