## Story

Là chủ dự án, tôi muốn cuối mỗi kịch bản hệ thống tự mở báo cáo và đối chiếu số liệu ở ba nơi với số kỳ vọng, để kết luận qua/hỏng dựa trên số thật chứ không dựa trên việc các bước có chạy hết hay không.

## Tiêu chí nghiệm thu (AC)

1. **AC-1:** Reconciler lấy đủ 3 nguồn cho mỗi chỉ tiêu kiểm đếm: số hiển thị trên giao diện báo cáo (qua worker), số từ API báo cáo của CRM, và số truy vấn trực tiếp từ DB của đích kiểm thử (chỉ đọc, qua cấu hình riêng, lọc đúng run_id/tenant test và khoảng ngày của kịch bản).
2. **AC-2:** Bảng chênh lệch cho từng chỉ tiêu: kỳ vọng / UI / API / DB / kết quả (Khớp hoặc Lệch + độ lệch). Một chỉ tiêu lệch ở bất kỳ nguồn nào → chỉ tiêu đó hỏng, và lần chạy bị đánh dấu hỏng ở khối kiểm đếm dù mọi bước thao tác đều qua.
3. **AC-3:** Lỗi đọc số trên UI do định dạng (ví dụ "900.000 đ") được xử lý bằng bộ phân tích số tiền dùng chung có test riêng — không so sánh chuỗi thô.
4. **AC-4:** Khi một nguồn không đọc được (API lỗi, DB không nối được), kết quả là "Không kiểm chứng được nguồn X" và lần chạy không được tính là qua.

### Bằng chứng theo AC
- **AC-1 ĐẠT:** Cả 3 nguồn được đọc cho mỗi chỉ tiêu trong test đối chiếu đầy đủ: UI từ outputs của worker, API qua **HTTP thật** tới máy chủ giả lập (test khẳng định query mang đúng `tuNgay=2026-11-07`, `tenant`, `runId`), DB qua executor với SQL tham số hoá lọc ngày/nhận diện test/tenant. DB chỉ-đọc được bảo đảm 2 lớp: cổng chặn SQL không phải SELECT/WITH ngay khi khởi tạo nguồn + giao dịch READ ONLY trong PgDbExecutor.
- **AC-2 ĐẠT:** Test "chỉ DB lệch" cho bảng: UI/API = 300.000 khớp, DB = 200.000 → dòng `lech`, `doLech = { db: -100000 }`, bảng HỎNG. Test tích hợp ở S4.3 chứng minh tiếp: API lệch +50.000 → **lần chạy bị đánh dấu HỎNG dù mọi bước thao tác đều QUA**, bước `kiem-dem` ghi HỎNG kèm tóm tắt.
- **AC-3 ĐẠT:** Bộ phân tích `parseSoTien/parseSoLuong` nằm ở `@autotest/oracle` (`src/so-tien.ts`), có test riêng 9 ca — gồm ca trung tâm "900.000 đ" → 900000 (định dạng từng làm hỏng spec 29.2/38.6 của CRM), gom nhóm, phần thập phân 0, và các ca từ chối định dạng mơ hồ thay vì đoán. Cả worker (đọc UI) và Reconciler đều dùng chung bộ này; test UI trả văn bản "chưa có dữ liệu" → chỉ tiêu thành "không kiểm chứng được" kèm văn bản gốc trong ghi chú, không so sánh chuỗi thô ở bất cứ đâu.
- **AC-4 ĐẠT:** Hai test mất nguồn: DB ném lỗi kết nối → cả 3 chỉ tiêu "Không kiểm chứng được nguồn DB", UI/API vẫn khớp nhưng bảng HỎNG và (qua executor) lần chạy không được tính là qua; API trả HTTP 500 → chỉ tiêu có nguồn api "không kiểm chứng được" kèm lý do. Chưa cấu hình `CRM_DB_READONLY_URL` → nguồn DB tự báo lỗi cấu hình theo cùng cơ chế.
